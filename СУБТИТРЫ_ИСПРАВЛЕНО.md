# ✅ Исправление работы субтитров - ФИНАЛЬНОЕ РЕШЕНИЕ (от ChatGPT)

## 🔧 Проблема
FFmpeg на Windows не мог правильно обработать пути в фильтрах `drawtext` из-за:
1. **Неправильного экранирования путей** - путь с `:` ломал парсер FFmpeg
2. **Отсутствия кавычек вокруг путей** - FFmpeg требует двойные кавычки для путей с пробелами/спецсимволами
3. **Слишком длинных команд** - при большом количестве субтитров командная строка становилась огромной

## ✅ Решение (рекомендация ChatGPT)

### 1️⃣ Правильное экранирование путей для FFmpeg
```python
@staticmethod
def _ffmpeg_escape_path(path: str) -> str:
    """
    Подготовить путь для использования внутри фильтра ffmpeg.
    -> переводим '\' в '/', экранируем двойные кавычки внутри и оборачиваем в двойные кавычки.
    """
    if not path:
        return '""'
    p = path.replace('\\', '/')
    p = p.replace('"', '\\"')   # экранируем двойные кавычки внутри пути
    return f'"{p}"'
```

### 2️⃣ Фильтры С ДВОЙНЫМИ КАВЫЧКАМИ вокруг путей
```python
# ❌ Неправильно (без кавычек или с одинарными)
f"drawtext=textfile={text_file}:fontfile={font_path}:..."

# ✅ Правильно (с двойными кавычками через escape функцию)
text_file_escaped = VideoProcessor._ffmpeg_escape_path(text_file)  # -> "C:/Users/.../file.txt"
font_path_escaped = VideoProcessor._ffmpeg_escape_path(font_path)  # -> "C:/Windows/Fonts/font.ttf"
f"drawtext=textfile={text_file_escaped}:fontfile={font_path_escaped}:..."
```

### 3️⃣ Чанковая обработка - СНИЖЕН chunk_size до 6
- Разбиваем фильтры на группы по **6** (было 10)
- Обрабатываем каждую группу отдельно
- Используем промежуточные файлы
- Добавлен DEBUG вывод для отладки

## 📊 Почему это работает

1. **Двойные кавычки** - FFmpeg корректно парсит пути с `:`, `/`, пробелами
2. **Escape `"` внутри** - защита от путей с кавычками
3. **`/` вместо `\`** - универсальный разделитель для Windows/Linux
4. **Меньший chunk_size** - снижает нагрузку на парсер FFmpeg
5. **Одинарные кавычки для enable** - защита от запятых в `between(t,...)`
